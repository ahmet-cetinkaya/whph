# MCP tool contract

This document is the implementation inventory for WHPH's local MCP adapter. It
names the public user actions; it is not a dump of internal maintenance
commands. Tool implementations are assembled as `McpToolDefinition` values by
the feature files named below and registered through `McpToolRegistry`.

The server is local-only (`http://127.0.0.1:44041/mcp` by default), disabled by
default, and available on Windows/Linux while WHPH runs and on Android only
while the app is resumed. Android supports application-usage tracking after the
user grants the operating system usage-access permission. MCP access grants,
tokens, server enablement, and scopes are deliberately not tools and never enter
sync, export, or restore data.

This table is the current binding inventory for the 89 implemented tool handlers
delivered in tasks 7-12. Task 14 covers verification that the assembled SDK
`tools/list` surface matches this inventory; platform-specific runtime
verification is tracked separately. Task 5 deliberately registers no placeholder
handler or fake success result to make an unimplemented action appear available.

## Contract conventions

- Tool names and field names are stable English identifiers. Date-only fields
  use `YYYY-MM-DD`; instants use offset-bearing ISO-8601; durations are seconds
  except fields explicitly ending in `Minutes`.
- List inputs share `pageSize` (default 50, maximum 200) and `cursor`; list
  outputs share `items` and `nextCursor`. Lists have deterministic ordering.
- Mutating existing records take `expectedRevision`. Omitted update fields are
  preserved; explicit `null` clears only nullable fields. An unknown update ID
  is `not_found`, never an upsert.
- Every input and output is a closed JSON object schema. All tools require every
  listed scope. A documented `anyOf(...)` is an explicit alternative set: the
  fixed scopes and at least one alternative are required. Discovery filters by
  current grants and the registry checks the current grant again on every call.
  MCP annotations are descriptive hints, never authorization.
- When a row lists scopes selected by an input category or owner, its feature
  handler performs that additional current-grant check before dispatch. The
  definition's fixed scope set is only the unconditional minimum.
- Output fields below omit the common error object
  `{error:{code,message,details?}}`. `revision` is an offset-bearing instant.
  User strings, including Markdown and instruction-like text, are data and are
  never inserted into server/tool instructions.
- Annotation codes are `R` read-only, `A` additive/non-idempotent, `M`
  destructive/idempotent mutation, and `D` destructive/non-idempotent. All are
  closed-world (`openWorldHint:false`).

Canonical scopes are `tasks:read|write|delete`, `habits:read|write|delete`,
`notes:read|write|delete`, `tags:read|write|delete`, `timers:read|write`,
`usage:read|write|delete|track`, `settings:read|write`, `sync:read|manage`,
`overview:read`, `app:read`, and `data:export|import`. Task-status operations
use task scopes.

Artifacts are not arbitrary files. A later resource adapter exposes only
metadata and bounded chunks belonging to the authenticated connection, using
opaque `whph://artifacts/{artifactId}`; it rechecks the original operation scope
on every read. The feature-resource inventory (`whph://app/context`,
`whph://tasks/{id}`, `whph://habits/{id}`, and `whph://notes/{id}`) shares these
serializers and permission checks; resource handlers are tracked separately from
this tool catalog.

## Enable and connect a client

MCP is disabled by default. In WHPH Settings, enable the local MCP server,
create a named connection, select only the scopes that client needs, and copy
the token when it is displayed. The token cannot be shown again. Configure a
client that supports generic Streamable HTTP with:

```text
URL: http://127.0.0.1:44041/mcp
Authorization: Bearer <token shown by WHPH>
```

Use the port displayed in Settings if it differs from `44041`. The token is an
HTTP `Authorization` header value, not a URL query parameter. WHPH deliberately
binds only to IPv4 loopback and does not provide a public-network endpoint or
OAuth discovery. Keep the app running. Windows and Linux may continue serving
while WHPH is in the system tray; Android serves only while the app lifecycle is
`resumed`. A stopped app, desktop exit, Android pause/background state, or
disabled server makes the endpoint unavailable. On Android, application-usage
tracking also requires the user to grant usage-access permission and is
available only while the app is `resumed`.

WHPH uses `mcp_dart` 2.4.2 with its stable protocol mode. A 2026-07-28 client
uses stateless discovery and sends the protocol version and request metadata on
each request. A 2025-11-25 client performs `initialize`, sends
`notifications/initialized`, and then uses its bound session. The SDK handles
both flows; clients should not combine their lifecycle rules. WHPH does not
claim native stdio support. A client that only accepts stdio requires a
separately evaluated local bridge.

Revoke a connection in Settings to invalidate its token and active legacy
session immediately. Scope changes and revocation are checked again when a
resource is read or a tool runs; discovery results are not authority.

## Resources

Resource discovery is grant-scoped. `resources/list` contains only fixed
resources currently registered for the connection, while
`resources/templates/list` contains only permitted templates. Reads are
poll-based; WHPH does not advertise prompts or resource subscriptions.

| URI                                             | Required scopes           | Content                                                                                                                      |
| ----------------------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `whph://app/context`                            | `app:read`                | Version, platform, local time zone, limits, supported feature summary, and current scopes; never credentials                 |
| `whph://tasks/{id}`                             | `tasks:read`, `tags:read` | The exact structured result of `whph_tasks_read`                                                                             |
| `whph://habits/{id}`                            | `habits:read`             | The exact structured result of `whph_habits_read`                                                                            |
| `whph://notes/{id}`                             | `notes:read`, `tags:read` | The exact structured result of `whph_notes_read`; Markdown remains untrusted user data                                       |
| `whph://artifacts/{artifactId}?offset={offset}` | `data:export`             | A caller-owned export artifact chunk of at most 256 KiB; omit `offset` for the first chunk and follow the returned `nextUri` |

Artifact IDs and record IDs are opaque. Absolute file paths, `file:` URIs,
unknown schemes, traversal segments, extra query parameters, negative or
out-of-range offsets, expired artifacts, and artifacts owned by another
connection are rejected. Resource errors do not disclose paths, database
details, tokens, or other records.
